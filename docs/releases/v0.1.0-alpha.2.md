# v0.1.0-alpha.2 — draft prerelease notes

Status: unpublished candidate. Publication requires explicit owner authorization after the release checklist is complete. This is a macOS/Codex Desktop read-only alpha, not stable v1.

## Changes since alpha.1

- Clarify macOS/Codex v1 scope, setup, restart verification, and deliberate connection recovery.
- Preserve the primary operation failure when lease release also fails. Report release or tombstone deletion failures after otherwise successful work; CLI success output waits for release.
- Classify oversized lock-owner metadata consistently as recovery required. Never automatically remove or steal incomplete locks.
- Preserve the refreshing marker after invalid or uncertain grants, preventing another attempt with the old refresh token.
- Use monotonic elapsed time for lock retry waits so system-clock adjustments cannot extend or shorten the contention budget; filesystem stalls are outside that budget.
- Add offline regression coverage for recovery, deadline metadata, ownership and tombstones. Update Node development type definitions; retain TypeScript 6.0.3 because the proposed 7.0.2 upgrade conflicts with current lint tooling.

## Installation and update

Use Node.js 24 or 26 and npm 10 or later. Once this tag is actually published, clone or fetch the repository, check out `v0.1.0-alpha.2`, then run `npm ci`, `npm run validate`, and `npm run build`. Before publication, use only the exact candidate commit recorded in the release PR.

Existing configured installations keep their local credentials and settings. Rebuild, then restart the local MCP process through Codex Desktop so it loads the new build. Confirm `get_setup_status` reports `0.1.0-alpha.2`. Status does not contact Etsy or prove a live connection. Do not run setup, reset, reauthorization, or live listing checks merely to update.

The default `dist/src/index.js` remains status-only; `dist/src/alpha.js` remains the opt-in read-only server. See the README for all STDIO fields. No migration, new environment variables, scopes, tool inputs, or Etsy writes are introduced.

## Evidence and limitations

Prior owner-authorized Mac OAuth/listing/detail and restart checks passed on alpha.1-era builds. Candidate evidence belongs in the [release checklist](../release-checklist.md#v010-alpha2-candidate); do not describe earlier checks as tests of this exact candidate.

The owner accepted the isolated Mac recovery drill on 1 November 2026 after offline and test-only Keychain modes passed eight stages and verified cleanup. Broader T-008 acceptance remains open: live Etsy revocation/reauthorization, interactive CLI recovery, and recovery of the healthy connection remain untested. Uncertain refreshes require deliberate recovery; do not clear state to retry old tokens. Lock retry waits use monotonic time. Wall-clock token freshness and expiry calculation after transport remain known timing limitations. Delegated OAuth is untested and, by owner decision on 1 November 2026, outside v1 acceptance in the very low-priority backlog. The owner previously accepted the unresolved Etsy terms interpretation risk; this is not a compliance determination. This release adds no capability or distribution model beyond the existing public alpha.

Published alpha.1 remains unchanged. No live Etsy request, credential access, reset, revocation, or reauthorization is part of release preparation.
