# v1.0.0-rc.1 — unpublished candidate

Historical unpublished rehearsal milestone, superseded by the [v1.0.0 candidate](v1.0.0.md). The exact rc.1 rehearsal used source `d4286682c659952bf19476aa702e3249b963efa8` and passed fresh-checkout install, 200 offline tests and build. It created no tag or release.

This candidate prepared macOS/Codex Desktop v1 for final review. No release or tag has been
published. The source SHA, local/fresh-checkout results, audit and required CI belong to the
candidate preparation PR; successful checks on earlier commits are baseline evidence only.

## What it delivers

- Local STDIO, one owner-authorized shop, macOS Keychain, and read-only listing review.
- Bounded active-listing pages and detail for IDs returned in the current server session.
- Client-generated title, description and tag suggestions grounded in returned facts.
  The [fabricated worked example](../listing-review-example.md) demonstrates the review.
- Fail-closed identity/grant checks and deliberate recovery for uncertain refreshes.
- Primary-error preservation, cleanup-only failure reporting, safe tombstone ownership and
  malformed owner metadata classification; monotonic lock retry waits.
- Distinct sanitized authorization, permission, rate-limit, timeout, service and data errors.
- Status from the last complete successful listing read: `verified_this_session`, verified
  numeric owner/shop IDs and UTC timestamp. Status makes no requests or credential reads;
  a later pending/failed read or restart clears it. It is not a current health check.

The default `dist/src/index.js` remains status-only; `dist/src/alpha.js` is the explicit read-only
entry point. No new Etsy endpoint, broader scope, listing mutation, buyer data, hosted service,
OpenAI API credential or plaintext credential fallback is added.

## Candidate installation and update

Use Node.js 24 or 26 and npm 10 or later. Before publication, fetch the repository and check out
the exact SHA from the preparation PR, not a nonexistent rc.1 tag. Run `npm ci`,
`npm run validate` and `npm run build`. Configure the existing Node command/absolute alpha
entry point/working directory as documented in the README. Status starts with `not_checked`.

Existing installations require no settings/credential migration. Rebuild and restart the local
MCP process in Codex so it loads the selected checkout. Confirm status version `1.0.0-rc.1`.
An update does not authorize a live read, reset or reauthorization. Normal owner-authorized reads
can subsequently establish session confirmation; a status call never does so implicitly.

To return to the published alpha.1, stop the process, select `v0.1.0-alpha.1`, reinstall/build
that checkout and restart its configured entry point. Keep local connection state intact.
This is a code rollback, not a remedy for revoked authorization or an uncertain refresh.
Do not delete state or retry an old refresh token as part of rollback.

## Evidence and limits

Historical Mac OAuth/listing/detail/restart and the accepted isolated Keychain recovery drill
remain accepted. The isolated drill verifies production modules with fabricated data; it does
not establish live revocation/reauthorization or interactive terminal recovery. Candidate
automation uses fabricated data and does not contact Etsy or access existing credentials.

Persisted token freshness still uses wall time and expiry calculated after transport. Backward
clock jumps can extend apparent freshness. The read path remains fail-closed on rejected
authorization; this is a reliability limitation to disposition in final review, not a claim
that live expiry failure was observed. Extra hardening is tracked separately from new features.

The last dependency review found 11 moderate development-chain entries from minimatch and zero
production findings. Record current audit results and final risk disposition in the preparation PR.
The maintainer recommends using repository tooling only with reviewed project configuration
and handling compatible advisory remediation separately; no force/peer-check bypass is applied.
This recommendation is not a claim that the advisory is fixed or risk-free.

The owner previously accepted the unresolved Etsy terms interpretation risk. This candidate
continues the existing local owner-authorized read-only scope and public-source distribution.
Delegated access is very low-priority backlog and unsupported. Other clients follow v1.
