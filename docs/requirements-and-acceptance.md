## Status meanings

**Implemented** describes code or documentation delivered. **Verified** names the checks actually
performed. **Accepted** requires owner acceptance where the criterion calls for it. These are
separate: passing tests does not publish a release or accept every untested scenario.

Tracker `Done` means that task's stated criteria are satisfied, not that the whole product is
released. `In Review` means implementation/evidence exists and the named acceptance decision is
pending. Deferred/backlog work is outside the active v1 delivery unless explicitly reprioritized.

## User workflows

| Use case                             | User action and expected result                                                                                                                                                      | Failure / boundary behavior                                                                                                                                        |
| ------------------------------------ | ------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------ | ------------------------------------------------------------------------------------------------------------------------------------------------------------------ |
| UC-01 — Install, start or update     | Follow README/operator steps, install locked dependencies, build, configure the selected STDIO entry point and read its version/status. Existing connection data needs no migration. | Status alone makes no Etsy/credential request. An exported-checkout rehearsal on the existing Mac passed; this is not a clean-machine acceptance claim.            |
| UC-02 — Authorize the owner's shop   | Enter credentials in hidden local prompts; owner consents in Etsy; grant and shop identity must match before connected success.                                                      | No credentials in chat/tool inputs; mismatched or unverifiable grants fail closed. Delegated access is outside v1.                                                 |
| UC-03 — Browse listings              | Ask for a bounded active-listing page and use the continuation offset when present.                                                                                                  | Fixed configured shop; errors give guidance without raw response data or automatic retries.                                                                        |
| UC-04 — Inspect a listing            | Ask for details of an ID returned in the same session.                                                                                                                               | Unknown IDs are refused; identity is checked again. A refreshed session/client may require listing the page again.                                                 |
| UC-05 — Review and draft             | Ask the client assistant for proposed copy grounded in retrieved facts. Review drafts before using them.                                                                             | Unknown claims become questions for the owner. Hostile listing instructions remain data. The application cannot publish the suggestions.                           |
| UC-06 — Understand a failure/recover | Read the diagnostic and follow the documented deliberate procedure. Busy means wait; uncertain refresh means stop retries and review recovery.                                       | Never steal a lock, clear a marker to retry an old token, or reset a healthy connection merely to test it. Live revocation/reconnection is not asserted as tested. |
| UC-07 — Confirm session identity     | After a successful listing operation, request status and see verified numeric owner/shop IDs and lastVerifiedAt.                                                                     | Memory-only evidence; a pending/failed newer read or restart clears it. Outside changes are not detected until read/restart. It is not a live health check.        |
| UC-08 — Release/update/roll back     | Review exact version, evidence, limits and update/rollback notes; owner separately authorizes publication.                                                                           | No v1 tag/release exists yet. Code rollback preserves local state and does not repair revoked or uncertain authorization.                                          |
